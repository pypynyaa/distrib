# Insomnia Market — описание проекта и чек-лист полного MVP

## 0. Актуальный статус на 10 июля 2026

MVP уже не является просто визуальным макетом: frontend работает с FastAPI backend и SQLite, есть роли артиста/команды, релизы, модерация, файлы, профиль, новости, промо-заявки, smart links, поддержка, уведомления и базовые финансы.

### Закрыто или доведено до рабочего состояния

- React frontend + FastAPI backend запускаются локально.
- Тёмная тема основная, светлая тема сохранена.
- Регистрация, вход, logout через backend-сессии.
- Кабинет артиста и админ-кабинет разделены по ролям.
- Профиль артиста сохраняется в backend: аватарка, описание, город/страна, жанры, соцсети.
- Релизы создаются с обложкой и аудиофайлом, отображаются в кабинете артиста и админке.
- Модерация релиза ручная: “Принят” / “Черновик” с причиной отклонения.
- Отклонённый релиз можно исправить и отправить повторно.
- UPC/ISRC и прослушивания вручную обновляются админом.
- Новости хранятся в backend, админ может создавать и удалять новости.
- Промо-заявки отправляются артистом и приходят в админку.
- Статусы промо-заявок меняются вручную.
- Smart links создаются, валидируются, копируются, удаляются и открываются публично по `/p/:slug`.
- Чат поддержки работает через backend: тикеты, сообщения, статусы, polling.
- Уведомления в кабинете сохраняются в backend, есть “прочитано”.
- Email-уведомления технически подключены через SMTP env-переменные, но требуют реальные SMTP-данные.
- Финансы артиста теперь считаются из backend: начислено, выплачено, в обработке, доступно к выплате.
- Заявка на выплату проверяет доступный баланс на frontend и backend.
- Ожидающая выплата временно уменьшает доступный баланс.
- Админка финансов умеет добавлять начисления, фильтровать заявки и ставить статус “Оплачено” / “Отклонено”.
- Админка кабинетов показывает реальные начисления и выплаченные суммы.
- Production build frontend проходит.
- Python backend проходит `py_compile`.
- API smoke по финансам прошёл: логин, начисление, баланс, заявка, отклонение.

### Критичные хвосты до “прям почти прод”

- Расширить статистику: сейчас прослушивания есть, но график и площадки ещё не настоящая time-series аналитика.
- Доделать мульти-трековые EP/альбомы: отдельные треки, отдельные аудиофайлы, отдельные ISRC.
- Добавить редактирование smart links и статистику переходов.
- Добавить редактирование новостей, черновики, обложки и Markdown/HTML редактор.
- Добавить причины блокировки аккаунтов и audit log действий админов.
- Добавить причину отклонения выплаты и прикрепление чека/подтверждения.
- Проверить и улучшить мобильную вёрстку всех страниц.
- Добавить восстановление пароля, подтверждение email, rate limit и срок жизни сессий.
- Перенести production-хранение файлов в S3/Supabase Storage/Cloudflare R2.
- Перенести базу с SQLite на PostgreSQL и добавить миграции.
- Настроить реальные SMTP-данные и проверить письма на боевом email.
- Подготовить юридические страницы: оферта, политика, правила выплат, правила модерации.
- Добавить полноценные backend/API/e2e тесты.
- Подготовить деплой backend + frontend + env + HTTPS + CORS под домен.

## 1. Что из себя представляет проект

Insomnia Market — это веб-платформа музыкальной дистрибуции для артистов и команды сервиса.  
Идея продукта: артист регистрируется на сайте, загружает релиз со всеми данными, команда Insomnia вручную проверяет релиз, принимает его или возвращает на доработку с причиной. После релиза команда вручную обновляет статистику, финансы, UPC/ISRC и статусы выплат.

Проект должен состоять из двух основных кабинетов:

1. Кабинет артиста.
2. Админ-кабинет команды Insomnia.

Кабинет артиста нужен, чтобы пользователь мог:

- зарегистрироваться и войти;
- заполнить профиль артиста;
- загрузить аватарку;
- загрузить релиз;
- загрузить обложку;
- загрузить аудиофайлы;
- указать данные релиза;
- отправить релиз на модерацию;
- видеть статус релиза;
- видеть причину отклонения;
- видеть UPC и ISRC после принятия;
- смотреть статистику;
- смотреть финансы;
- запросить выплату;
- создать промо-ссылку/smart link;
- отправить заявку на промо-поддержку;
- писать в чат поддержки;
- читать новости сервиса;
- получать уведомления в кабинете и на почту.

Админ-кабинет нужен, чтобы команда Insomnia могла:

- видеть все релизы всех пользователей;
- модерировать релизы;
- принимать релизы;
- отклонять релизы с причиной;
- вручную вписывать UPC и ISRC;
- вручную обновлять прослушивания;
- вручную обновлять финансы;
- видеть заявки на выплаты;
- отмечать выплаты как оплаченные;
- видеть все зарегистрированные кабинеты;
- блокировать и разблокировать пользователей;
- отвечать в чате поддержки;
- видеть промо-заявки;
- управлять новостями;
- добавлять и удалять администраторов;
- получать системные уведомления.

Главный принцип проекта: на старте почти всё управляется вручную командой Insomnia. Автоматизация может появиться позже, но MVP должен быть стабильным, понятным и рабочим.

## 2. Какой функционал должен быть на выходе

На выходе должен получиться полноценный рабочий MVP, а не просто визуальный макет.  
Каждая кнопка должна либо выполнять действие, либо открывать понятное окно/страницу, либо показывать пользователю, почему действие сейчас невозможно.

Целевой результат:

- рабочий React frontend;
- рабочий Python/FastAPI backend;
- база данных;
- авторизация;
- роли пользователей;
- загрузка файлов;
- хранение релизов;
- ручная модерация;
- email-уведомления;
- чат поддержки;
- smart links;
- финансы и выплаты;
- админ-панель;
- деплой frontend и backend;
- возможность показывать заказчику живую систему.

## 3. Пользовательские роли

### Обычный пользователь / артист

Обычный пользователь не должен иметь доступ к функциям команды.  
Он видит только свои релизы, свои финансы, свои промо-ссылки, свои заявки и свои сообщения поддержки.

Доступ артиста:

- главная;
- релизы;
- загрузка релиза;
- статистика;
- финансы;
- новости;
- промо-поддержка;
- промо-ссылки;
- поддержка;
- профиль.

### Администратор / команда Insomnia

Администратор видит рабочий кабинет команды.

Доступ админа:

- все релизы;
- все пользователи;
- все заявки на выплаты;
- все заявки на промо;
- все тикеты поддержки;
- управление новостями;
- управление администраторами;
- ручная модерация;
- ручное обновление данных.

### Владелец

Владелец имеет полный доступ, включая добавление и удаление администраторов.
